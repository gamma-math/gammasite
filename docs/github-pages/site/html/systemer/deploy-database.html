Deploy Database

Manuelt GitHub Actions-workflow til at sammenligne, validere, planlægge og deploye databaseskemaer for GamMaSite.

  1. Åbn Actions i GitHub, og vælg Database schema management.
  2. Vælg database: mysql for applikationsdatabasen hos Simply eller postgres for Finance-databasen hos Neon.
  3. Vælg environment: TEST eller PROD. Workflowet bruger det valgte GitHub Environment og dets secrets.
  4. Vælg en handling: diff, validate, plan eller deploy.
  5. Ved et deploy kontrollerer workflowet indstillingerne, installerer database-driverne, viser planen, udfører den godkendte ændring og validerer derefter skemaet igen.

Start altid med diff eller plan. Brug først deploy, når planen er gennemlæst, og den valgte database og det valgte environment er korrekte.

Schema Source of Truth

Workflowet sammenligner den valgte database med de versionsstyrede SQL-definitioner i repositoryet.

DatabaseLokal definitionGitHub Secret
MySQLsrc/database/mysql/gam_ma_dk_db.sqlCONNECTION_STRING
PostgreSQL Financesrc/database/postgres/finance.sqlFINANCE_CONNECTION_STRING

Secrets vises ikke i workflow-loggen. CLI'en skriver kun en redacted forbindelsesbeskrivelse uden password.

Deploy-godkendelser

Workflowet har tre deploy-relaterede checkboxes i Run workflow. De bruges ved valg af deploy:

CheckboxHvornår skal den være valgt?
confirm_deploymentAltid ved deploy. Bekræfter, at workflowet må udføre SQL.
allow_riskKun hvis planen indeholder indexes, constraints eller views, som CLI'en markerer som risikable.
confirm_productionKun ved deploy til PROD. Bekræfter eksplicit production-miljøet.

GitHub Environment PROD bør desuden være konfigureret med required reviewers og eventuelle branch restrictions.

Workflowets runs

  1. Check-out repository: henter SQL Source of Truth og CLI-koden.
  2. Add Python: klargør Python 3.13 og pip-cache.
  3. Validate deployment settings: kontrollerer valgt schema-fil, relevant secret og deploy-godkendelser.
  4. Install database tooling: installerer PyMySQL og psycopg.
  5. Verify database tooling: kontrollerer driverne og CLI'ens help-output.
  6. Generate deployment plan: kører kun ved deploy og skriver planen uden databaseændringer.
  7. Deploy database schema: kører kun efter de nødvendige checkboxes.
  8. Validate deployed schema: kører efter deploy og stopper workflowet ved en afvigelse.

Sikkerhedsregler

  • Workflowet sletter ikke automatisk tabeller, kolonner eller data.
  • Destruktive, tvetydige eller inkompatible ændringer blokeres og skal håndteres separat.
  • Read-only handlinger bruger en read-only databasesession.
  • Deploys til samme database og environment kører ikke parallelt.
  • Website-workflowet Build and deploy validerer skemaerne, men ændrer ikke databaserne.

Kontrollér altid environment. Et deploy til PROD bruger de production secrets, som er konfigureret på GitHub Environment. Del aldrig connection strings eller passwords i issues, logs eller dokumentationen.
