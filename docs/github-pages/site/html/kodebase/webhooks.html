GamMa modtager statusopdateringer fra Stripe og MobilePay på to offentlige HTTPS-endpoints. Webhooks må ikke pege på localhost eller en lokal tunnel i test- eller produktionsmiljøet.

Simply og den offentlige webserver

Simply er værten for webserveren. Der oprettes ikke en separat webhook inde i Simply; webhooken oprettes hos Stripe eller MobilePay og kalder den URL, som den deployede GamMaSite-applikation eksponerer.

  1. Kontrollér at test- eller produktionsdomænet peger på det rigtige Simply-site, og at HTTPS-certifikatet er aktivt.
  2. Deploy den aktuelle version via GitHub Actions med det korrekte environment: TEST eller PROD.
  3. Kontrollér at pipeline-konfigurationen indeholder webhook-secretet og de relevante betalingscredentials for samme environment.
  4. Brug endpointet fra tabellen ovenfor, når webhooken oprettes hos betalingsudbyderen.
  5. Kontrollér efter oprettelsen serverlog og betalingsudbyderens delivery-log for en HTTP 2xx-respons.

Stripe

Stripe-webhooken behandler gennemførte Checkout-betalinger, abonnementer og fakturabetalinger. Den opdaterer blandt andet eventbetalinger, medlemsstatus og betalingsaftaler.

  1. Deploy den relevante version til Simply via GitHub Actions. Kontrollér, at test eller produktion har korrekt HTTPS og domæne.
  2. Åbn den relevante Stripe-konto, og gå til Developers → Webhooks.
  3. Vælg Add endpoint, indsæt den offentlige URL ovenfor, og vælg kun de events, som applikationen håndterer: checkout.session.completed, checkout.session.async_payment_succeeded, customer.subscription.created, customer.subscription.updated, customer.subscription.deleted, invoice.paid, invoice.payment_failed og invoice.payment_action_required.
  4. Gem endpointets signing secret som STRIPE_WEBHOOK_SECRET i det samme GitHub Environment, som deploymentet bruger. Secret må ikke skrives i repositoryet.
  5. Send en test event fra Stripe, og kontrollér HTTP 2xx, applikationslog og at den forventede betaling eller betalingsaftale opdateres.

Stripe beskriver dashboard- og API-oprettelse af webhook endpoints i Stripe Webhook Endpoints.

MobilePay

MobilePay-webhooken modtager ePayment- og Recurring-hændelser på samme endpoint. Det er især vigtigt at registrere både aftalehændelser og charge-hændelser for gentagne betalinger.

  1. Deploy til Simply, og kontrollér at den offentlige MobilePay-URL svarer over HTTPS. Simply hoster endpointet; selve webhook-registreringen oprettes hos MobilePay.
  2. Vælg test- eller produktionsmiljøet hos MobilePay, og brug credentials fra det samme miljø. Testcredentials må ikke bruges i produktion.
  3. Installér scriptets afhængigheder fra src/scripts/vipps/requirements.txt. Kørselsfilen er src/scripts/vipps/vipps.py, og den komplette opsætning står i src/scripts/vipps/README.md.
  4. Se eksisterende webhooks med --list-webhooks, og notér ID'et på den webhook, der skal udskiftes.
  5. Opret en ny webhook med --rotate-webhook <gammelt-webhook-id> <offentlig-url>. Scriptet opretter den nye webhook og verificerer URL'en, men sletter ikke den gamle endnu.
  6. Gem webhook-hemmeligheden i GitHub Environment som VIPPS_WEBHOOK_SECRET. Pipelinen skriver den til MobilePay:WebhookSecret; secretet må ikke committes.
  7. Deploy den nye secret, gennemfør en testbetaling, og kontrollér HTTP 2xx samt at betalingen eller betalingsaftalen opdateres.
  8. Slet først den gamle webhook med --delete-webhook <gammelt-webhook-id>, når den nye er verificeret.

Ved en første oprettelse uden en gammel webhook kan --register-webhook bruges. Scriptet viser secretet ved oprettelsen, så det skal gemmes med det samme i det korrekte GitHub Environment.

MobilePay beskriver oprettelse og eventtyper i Webhooks API-guiden og eventoversigten.

Efter en ændring skal webhooken testes i det miljø, hvor den er registreret. En lokal Stripe CLI-forward eller Cloudflare-tunnel tester kun lokal udvikling og må ikke bruges som permanent URL.
