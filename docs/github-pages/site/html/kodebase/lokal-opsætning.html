Kode · Lokal opsætning

Start GamMaSite, MySQL 8 og Finance PostgreSQL 16 med Docker Compose. Start Stripe CLI og Cloudflare-tunnel samlet, når lokale webhooks skal testes.

Forudsætninger

  • Docker Engine eller Docker Desktop med Docker Compose v2.
  • Docker Desktop skal køre med Linux-containere.
  • Vipps-credentials, hvis lokale Vipps-webhooks skal registreres eller roteres.
  • En lokal Stripe test-mode restricted API-key, hvis Stripe CLI skal bruges.

Brug kun testcredentials lokalt, og commit aldrig lokale miljøfiler eller secrets.

1. Før du starter

  1. Åbn en terminal i repositoryets rod, og gå til den lokale udviklingsservice: 
    cd src/services/local-development
  2. En lokal .env er valgfri ved almindelig opstart. Compose har lokale standardværdier for databaser og porte.
  3. Brug .env.example som oversigt over understøttede variabelnavne. STRIPE_WEBHOOK_SECRET og VIPPS_WEBHOOK_SECRET skal ikke udfyldes manuelt; integrationsscripts genererer dem.
  4. Kontrollér Compose-konfigurationen uden at starte containere: 
    docker compose config --quiet

2. Første opstart

  1. Byg images, og start GamMaSite samt begge databaser: 
    docker compose up -d --build
  2. Kontrollér containerstatus: 
    docker compose ps
  3. Kontrollér Compose, container-health, databaseforbindelser og den lokale HTTP-adresse: 
    docker compose --profile tools run --rm --build tools scripts/validate.sh
  4. Hvis databaserne er helt tomme, indlæs testdata eksplicit: 
    docker compose --profile tools run --rm --build seed

Seed-servicen kører MySQL- og PostgreSQL-seed inde i Docker, afviser ikke-tomme databaser og registrerer, hvis seed allerede er kørt. Den ændrer ikke databasevolumes ved almindelig opstart.

3. Start Stripe CLI og webhook-tunnel

Start Stripe CLI og Cloudflare Quick Tunnel samlet som detached Compose-services:

docker compose --profile tools run --rm --build tools scripts/integrations-up.sh
  1. Sørg for, at GamMaSite allerede kører med docker compose up -d.
  2. Sørg for, at STRIPE_SECRET_API_KEY i den lokale .env er en Stripe test-mode restricted API-key.
  3. Kør integrationskommandoen ovenfor.
  4. Scriptet starter Stripe CLI og tunnelen, gemmer det dynamiske STRIPE_WEBHOOK_SECRET og PUBLIC_WEBHOOK_BASE_URL i den lokale .env og genstarter kun app.

Stripe CLI forwarder til:

/api/payments/stripe/webhook

Den restricted Stripe test-key skal mindst have Debugging Tools → Write (stripecli_session_write) for at Stripe CLI kan oprette en listen-session. Backendens Stripe-funktioner kræver desuden adgang til Checkout Sessions, Products, Prices og Subscriptions samt læseadgang til Invoices.

Kontrollér integrationsservices:

docker compose --profile integrations ps
docker compose --profile integrations logs -f stripe-cli tunnel

Stop kun integrationsservices:

docker compose --profile integrations stop stripe-cli tunnel

4. Registrér eller rotér Vipps/MobilePay-webhook

Tunnelen skal være startet med scripts/integrations-up.sh, før Vipps-webhooken registreres. Den eksterne webhook-URL bliver dermed:

${PUBLIC_WEBHOOK_BASE_URL}/api/payments/vipps/webhook
  1. Vis de aktive webhooks og deres ID’er: 
    docker compose --profile tools run --rm --build tools scripts/vipps-webhook.sh list
  2. Ved første registrering opret en ny webhook: 
    docker compose --profile tools run --rm --build tools scripts/vipps-webhook.sh register
  3. Ved rotation bruges ID’et før kolon i listen som OLD_WEBHOOK_ID: 
    docker compose --profile tools run --rm --build tools scripts/vipps-webhook.sh rotate OLD_WEBHOOK_ID

Vipps-scriptet bruger Vipps-credentials og VIPPS_MSN fra den lokale .env, gemmer den nye VIPPS_WEBHOOK_SECRET lokalt og genstarter kun app. Den gamle webhook slettes ikke automatisk.

5. Genbyg kun frontend og backend

Hvis databaserne allerede kører, og der kun er ændret i applikationskode eller frontend:

docker compose up -d --build --no-deps app

Ved behov for et helt nyt image uden Docker-cache:

docker compose build --no-cache app
docker compose up -d --no-deps app

Databaser og volumes bliver ikke genbygget eller ændret af disse kommandoer.

6. Daglig brug

Start eksisterende containere igen uden rebuild:

docker compose up -d

Genstart kun hjemmesiden:

docker compose restart app

Se status og logs:

docker compose ps
docker compose logs -f app
docker compose logs -f mysql finance-postgres

Kør en engangskommando i app-imaget:

docker compose run --rm --no-deps app <kommando>

Stop hele stacken uden at slette database- eller medievolumes:

docker compose down

GamMaSitehttp://localhost:5000
MySQLlocalhost:3306

Databaseportene bindes kun til localhost og kan ændres i den lokale .env.

Databaseinitialisering

MySQL initialiseres første gang et tomt named volume oprettes med SQL/AspNetMysql.test.sql. Finance PostgreSQL initialiseres med SQL/finance/PostgreSQLTest.sql. Testdata køres kun eksplicit med seed-servicen.

Der er ikke fundet EF Core migrationsfiler i backendprojektet. Schemaændringer skal derfor håndteres som særskilte, gennemgåede SQL-ændringer.

Brug ikke docker compose down -v, medmindre alle lokale database- og mediedata med vilje må slettes. Ændringer i init-SQL køres ikke automatisk igen på eksisterende volumes.

Almindelige fejl

  • Docker Linux-engine mangler: Start Docker Desktop, kontrollér med docker info, at både Client og Server svarer, og kør derefter opstarten igen.
  • Porten er optaget: Brug eksempelvis MYSQL_PORT=3307 eller FINANCE_POSTGRES_PORT=5434 i den lokale .env.
  • Database ikke healthy: Se docker compose logs mysql eller docker compose logs finance-postgres.
  • Appen starter ikke: Se docker compose logs app. Appen venter på begge database-healthchecks.
  • Collation-fejl under seed: Kør seed-kommandoen igen. Seed-servicen harmoniserer den lokale claims-tabel.
  • Stripe-fejl: Kontrollér Stripe CLI-loggen, test-mode API-key permissions og at secretet stammer fra den aktive CLI-session.
  • MobilePay unauthorized: Kontrollér VIPPS_WEBHOOK_SECRET, webhook-URL’en og at tunnel-containeren kører.

Den lokale Cloudflare Quick Tunnel-URL er midlertidig og må ikke bruges som permanent TEST- eller PROD-webhook. Lokale secrets må ikke committes.
