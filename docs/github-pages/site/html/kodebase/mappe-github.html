GitHub Actions-workflows

Mappen .github/workflows/ indeholder de tre manuelle pipelines, som henholdsvis bygger og deployer applikationen, styrer databaseskemaer og udgiver den statiske dokumentation. Alle tre workflows køres fra GitHub Actions og bruger repositoryets Source of Truth-filer.

Pipeline-oversigt

Build and deploy

pipeline.yml er applikationens samlede release-pipeline. Den installerer Python 3.13, .NET 10 og Node.js 22, tjekker alle nødvendige deployment-indstillinger og validerer både MySQL- og Finance PostgreSQL-skemaet før build.

  1. Frontendens npm-pakker gendannes med npm ci, hvorefter Vite-build og Node-tests køres.
  2. Solutionen restores, og backendens xUnit-tests køres. Testresultater uploades som artifact, også hvis et senere trin fejler.
  3. Backendens appsettings.json får miljøspecifikke værdier fra GitHub Environment secrets/variables.
  4. Projektet publiceres self-contained til win-x86 og deployes til den valgte TEST- eller PROD-destination via MSDeploy.

Workflowet er den normale applikationsudgivelse. Database-deployment foregår som et separat, eksplicit workflow.

Database schema management

database-deployment.yml er den kontrollerede adgang til schema-værktøjet. Den kan køre observationer uden ændringer eller en eksplicit bekræftet deployment.

  • diff, validate og plan må ikke skrive til databasen.
  • deploy kræver confirm_deployment; PROD kræver desuden confirm_production.
  • allow_risk kan kun bruges ved deployment og giver tilladelse til de schemaændringer, som værktøjet markerer som risikable.
  • Efter en deployment køres validate automatisk mod samme miljø.

Workflowet kører på Windows Server 2025, bruger Python 3.13 og installerer PyMySQL og psycopg fra database-servicekravene.

Deploy GitHub Pages

deploy-github-pages.yml publicerer dokumentationen uafhængigt af applikationsdeployments. Build-jobbet kører docs/github-pages/generate-code-docs.mjs _site, så de genererede filoversigter afspejler repositoryets versionsstyrede filer.

Workflowet bruger kun contents: read, pages: write og id-token: write. Det færdige artifact sendes til GitHub Pages, og deployment-jobbet eksponerer den publicerede Pages-URL.

Secrets, connection strings og miljøspecifikke værdier hører hjemme i GitHub Environments. De må ikke skrives i workflow-filer, SQL-filer eller den publicerede dokumentation.
